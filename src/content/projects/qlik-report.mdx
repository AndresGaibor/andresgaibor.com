## El problema

Los procesos de reporting empresarial suelen mezclar lógica de negocio, transformaciones, ejecución remota y generación de archivos. Cuando el volumen crece, una descarga manual deja de ser una solución viable.

## Lo que construí

Diseñé una aplicación que centraliza la definición del reporte, prepara la consulta, ejecuta trabajos asíncronos y organiza las descargas sin exigir que el navegador mantenga todo el dataset en memoria.

El sistema separa claramente **compilación**, **ejecución**, **seguimiento** y **descarga**. Esa división facilita optimizar cada etapa sin acoplar la interfaz al motor de datos.

## Decisiones técnicas

- El procesamiento pesado ocurre fuera del navegador.
- Las exportaciones se tratan como trabajos asíncronos y observables.
- Los archivos grandes pueden dividirse durante el flujo de descarga.
- Las consultas se generan buscando SQL legible y aprovechando el esquema disponible.
- La interfaz muestra estados y metadatos útiles sin exponer detalles internos innecesarios.

## Qué demuestra

Este proyecto combina frontend, backend, integración con APIs, compilación de lógica, BigQuery, almacenamiento de objetos y diseño de flujos para datos de gran tamaño.
